# 测试用例设计

适用范围：单元测试与接口测试（vitest / jest / pytest 均可）。

## 硬规则

1. **一个用例只断言一件事**，用例名说明「场景 → 期望」，读名字就懂，不用看代码：`it("空输入时不写入磁盘")`。
2. **结构固定为 准备 / 执行 / 断言**（AAA），三段之间空一行；不要在断言里再做副作用操作。
3. **测行为，不测实现**：断言输入输出与可观察状态，不断言内部私有函数被调几次、私有字段叫什么。
4. **边界必须覆盖**：空、单个、最大、超长、非法类型、缺失必填、重复提交。给一张边界表再写用例，别想到哪写到哪。
5. **错误路径和正常路径同等对待**：每个可能失败的分支至少一条用例，断言错误信息可读。
6. **测试必须确定性**：不依赖当前时间、网络、真实用户目录、执行顺序。时间用注入的 `now()`，随机用固定种子，临时目录用完删。
7. **每个用例自己准备数据**，不复用上一个用例留下的状态；共享状态的用例会互相污染，调试成本高于收益。
8. **不 mock 被测对象本身**。只 mock 边界（网络、时钟、文件系统、第三方 SDK）。
9. **回归用例要能复现原缺陷**：修 bug 时先写下会失败的用例，再改代码，最后确认它变绿。
10. **不追求覆盖率数字**，但新增分支必须有对应用例；一个文件 100% 行覆盖却只测了快乐路径，等于没测。

## 输出约定

- 用例文件名与被测文件同名：`diff.ts` → `diff.test.ts`。
- 一组相关用例用 `describe` 按行为分组，不按函数分组。
- 给出可以直接运行的命令，以及预期输出（几条通过）。

## 自检清单

- [ ] 正常路径 + 每类错误路径都有用例
- [ ] 边界表里每一项都落到某条用例
- [ ] 没有 `sleep` 等待、没有真实网络、没有依赖本机绝对路径
- [ ] 断言具体到值与文案，而不是 `toBeTruthy()`
- [ ] 用例之间可以任意顺序单独执行

## 常见反例

```ts
// 反例：依赖真实时间、断言太松、一个用例测四件事
it("works", async () => {
  const out = await save({ a: 1 });
  expect(out).toBeTruthy();
  expect(Date.now() - start).toBeLessThan(1000);
});
```

```ts
// 正例：注入时钟、单点断言、边界表驱动
const now = () => 1_700_000_000_000;

it("覆盖旧文件前先备份到 undo 目录", async () => {
  const fs = memfs({ "a.ts": "old" });

  await saveFile(fs, "a.ts", "new", { now });

  expect(fs.read(".zxz/undo/2023-11-14T22-13-20/a.ts")).toBe("old");
});

it.each([
  ["../evil", "不能包含 .."],
  ["C:/x", "不能带盘符"],
])("拒绝越界路径 %s", (path, msg) => {
  expect(relPathError(path)).toBe(msg);
});
```
