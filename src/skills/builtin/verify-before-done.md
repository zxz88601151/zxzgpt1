# 完成前取证

核心一条：**没有证据就不要下结论。** 把「应该」「大概」「看起来没问题」当作禁语。

本工具没有终端，模型不能真的跑 `npm test`。这不是放宽要求的理由——是要求你说清「我验证到哪一步、哪一步没法验证」。

## 铁律

```
没看过的东西，不能说它对了。
```

## 三步取证

声称任何「完成 / 修好 / 通过」之前，按顺序走完：

1. **回读**：把这次写的文件重新读一遍（`@@read: <路径>`），不要凭记忆描述内容。
2. **对照**：把用户的要求拆成条目，逐条标「已满足 / 未满足 / 无法验证」，不合并、不含糊。
3. **定量**：说清动了几个文件、加了几行删了几行。数字来自 diff，不来自印象。

三步缺一步，就是在猜。

## 本工具能拿到什么证据

| 想证明的事 | 能用的证据 | 不能用的 |
| --- | --- | --- |
| 代码写进去了 | 回读文件内容 + 回执卡上的 `+N −N` | 「我已经写好了」 |
| 改的是对的地方 | diff 里每个 hunk 能对上需求 | 文件总数对了 |
| 没碰不该碰的 | diff 里没出现无关文件 | 「我只改了需要改的」 |
| 逻辑正确 | 逐行读一遍关键分支 | 语法看起来没问题 |
| 能编译 / 能跑 | **无法验证**，必须明说 | 「应该能跑」 |

最后一格是关键：**不能验证就说不验证**，不要用别的东西冒充。

## 常见失败

| 你可能会说 | 实际需要 | 不够 |
| --- | --- | --- |
| 测试通过 | 测试命令的真实输出 | 上次跑过 / 应该能过 |
| 构建成功 | 构建命令 exit 0 | 类型检查过了 |
| bug 修好了 | 原始症状复现后不再出现 | 代码改了 |
| 需求满足 | 逐条清单对上 | 测试通过 |
| 文件已写入 | 回执 + 回读内容 | 模型说写了 |

## 该停下的信号

- 说出「应该」「大概率」「按理说」
- 在验证前就说「好了」「完成」「没问题」
- 用「其他部分都没问题」代替「这一部分我没验证」
- 只验证了容易验证的那一半
- 觉得「这次就不用查了吧」

以上任何一条出现，回去走三步取证。

## 输出格式

收尾时按这个结构说话，不要写成一段散文：

```
改动：<文件> +<n> −<m>；<文件> +<n> −<m>
对照需求：
  ✅ <需求 1> — <证据：diff 里第几处 / 回读到什么>
  ⚠️ <需求 2> — 无法验证，因 <原因>
  ❌ <需求 3> — 未满足，因为 <原因>
未验证：<具体是什么，需要你本地跑什么命令>
```

⚠️ 和 ❌ 必须写出来。只报喜的报告等于没报告。

## 反例与正例

```
❌ 已完成！所有文件都写好了，代码应该没问题，你可以试试看。

✅ 改动：src/lib/diff.ts +42 −7；src/lib/diff.test.ts +38 −0
   对照需求：
     ✅ 行级 diff — diff.ts 里 diffLines 按 LCS 逐行比对
     ✅ 大文件保护 — 中间块超 400 万格退化为整块替换
     ⚠️ 性能 — 无法验证，需要你本地跑 npx vitest run src/lib/diff.test.ts
   未验证：测试是否通过（本工具不能执行命令）
```
