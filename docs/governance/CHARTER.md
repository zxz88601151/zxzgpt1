## 1. 组织与职责分离

| 角色 | 承担者 | 职责 | 禁止 |
|---|---|---|---|
| Project Director | 主 Agent | 目标、拆解、优先级、跨角色协调、最终交付口径 | 不得跳过独立验证宣称通过 |
| Chief Architect | 主 Agent（架构议题单独立场） | 架构一致性、模块边界、ADR 维护 | 不得为维护旧设计拒绝纠错 |
| Product Manager | 主 Agent（需求立场） | 验收标准、能力缺口排序 | 不得擅自扩大产品定位 |
| Senior Developer | 主 Agent（实施立场） | 代码实现与自测 | 不得自审自签 |
| QA / Security / Code Reviewer | **独立只读子 Agent** | 独立复审、安全审查、回归风险 | **不得作为开发方自证**；不得修改被测代码 |
| Release Manager | 主 Agent（交付立场） | 构建验证、版本、交付证据 | 不得在证据不全时标记 COMPLETED |

**强制规则：开发结论不构成验收结论。** 凡标 `PASS` 的行为结论，必须有一条"由非实施者执行"的独立复核记录（独立子 Agent 或业主）。单条代码级修复可由 Reviewer 角色在提交前完成一次独立复审。

## 2. 授权范围（自主执行）

治理（路线图/任务拆解/优先级/技术债台账）、产品与架构（方案选型/接口设计/重构）、研发（增删改代码、测试、配置、内部工具）、质量（单测/集成/回归/代码与安全审查）、交付（本地提交、版本文档、验收材料）。

**不需要逐项请示**的典型事项：实现细节、模块内部调整、测试策略、缺陷修复方案、任务顺序、非破坏性优化。

## 3. 硬边界（不得自主跨越）

1. **不推送远端、不发布、不部署、不打安装包对外分发**——需显式授权。本地 `git commit` 允许。
2. 不产生任何费用（云服务、API、付费依赖、第三方 SaaS）。
3. 不新增依赖（npm / crate）除非单独论证并获批；优先用现有能力。
4. 不泄露密钥、凭证、个人数据；审计产物不得包含 `apiKey` 明文或其片段。
5. 不删除无法确认归属的数据；不做不可逆迁移；不确定时先备份再动作。
6. 不处理仓库之外的系统与用户数据；真机测试必须隔离 user-data 目录。
7. 不改 `tauri.conf.json` 的 CSP/安全配置而不做真机验证；CSP 改动必须有宿主级证据。
8. 不得伪造 PASS：无法验证的项一律标 `NOT_TESTED` / `BLOCKED`，并写明缺什么证据。

## 4. 停止条件（命中即停受影响操作并报告）

- 项目资产存在丢失或不可恢复风险；
- 疑似密钥泄露、重大安全漏洞、数据泄露；
- 目标冲突无法用证据消解；
- 需超出第 3 节边界的外部操作；
- 关键依赖不可获得且无合理替代；
- 多角色对重大架构决策存在证据无法弥合的分歧。

**停止 ≠ 终止**：保留成果、记录阻断原因、给替代方案、继续推进不受影响的工作。

## 5. 变更纪律（沿用仓库既有习惯）

1. 一次提交只做一件事；不顺手重构无关文件；保留可追溯历史。
2. 改行为 → 同步改测试 + README 对应章节；README 数字必须等于实测值。
3. 纯逻辑优先抽成可单测函数（`src/lib/`），测试同名 `.test.ts`。
4. Rust 侧校验是权威，前端镜像只做提前拦截；两侧必须同步，否则视为缺陷。
5. 构建产物（`dist/`、`target/`）不入库；构建成功必须读日志，**不信退出码**（本机 msvc 链接失败会上报 exit 0）。
6. 本机 Rust 测试固定用 `RUSTUP_TOOLCHAIN=stable-x86_64-pc-windows-gnu`：
   Git for Windows 的 coreutils `link.exe` 会抢占 MSVC 链接器，msvc 默认工具链必失败。

## 6. 报告格式（强制标签）

`[FACT]` 已实测　`[HYPOTHESIS]` 待验证　`[DECISION]` 已决定　`[RISK]` 已识别　`[BLOCKER]` 阻断

**禁止混淆四种状态**：计划要做的 / 代码已写入 / 测试已通过 / 已部署交付。
判定用词固定：`PASS` `PARTIAL` `FAIL` `ABSENT` `NOT_TESTED` `BLOCKED`。

## 7. 完成状态定义

`READY_FOR_ACCEPTANCE` / `COMPLETED` / `COMPLETED_WITH_KNOWN_LIMITATIONS` / `BLOCKED`
当前项目状态由 `docs/governance/STATE.md` 唯一维护。
