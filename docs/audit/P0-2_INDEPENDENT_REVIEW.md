## 3. Markdown 解析顺序审查（C3，重点）

当前 renderInline 顺序：①链接正则（原始输入）→ ②`escapeHtml(text)` → ③裸链接正则 → ④强调 → ⑤换行 → ⑥占位符还原。逐项：

| 检查项 | 结果 | 证据 |
|---|---|---|
| 链接正则先于转义的安全性 | label 在 img 分支经 escapeAttr（属性位）/ a 分支经 escapeHtml（文本位），均不依赖预转义 | 代码证明 |
| 占位符机制 | `keep()` 生成 `\u0000T<n>\u0000`，escapeHtml 不触碰 `\u0000`/`T`/数字，占位符在 ② 后存活；还原正则要求 `\u0000` 包裹，裸 `T0` 字面量不会被误还原（实测 N1：输入裸 `T0` 原样直出）；用户输入即使含真 `\u0000T0\u0000`，替换结果也是模块自身生成的安全 HTML 或 `undefined` 字符串，**无法注入用户数据** | 代码证明 + 实测 N1 |
| 代码块/行内代码隔离 | renderMarkdown 在调用 renderInline **之前**已用 `\u0000B/\u0000I` 占位符抽出代码（md.ts:127-134），renderInline 永远看不到原始代码内容 | 代码证明 |
| 嵌套/组合 | `[f(x)](https://a)`、`[g](https://b(y))` 平衡括号正确；`**[b](u)**`、`*[i](u)*` 强调与链接组合输出结构正确（实测 N2/N3） | 实测 |
| 裸链接分支 | 字符集 `[^\s<)"']` 排除引号与 `<`；`&` 已被 ② 编码为 `&amp;`，插值后单次编码（PoC #5 旁证：裸链接 `?x=1&y=2` → `&amp;`） | 代码证明 + 实测 |
| title 语法 | `[a](u "t")` → href 值内 `&quot;t&quot;`，单一属性闭合正确（PoC #7） | 实测 |
| 其余插值点 | 穷举 md.ts 22 处 `${}`：仅 48/49/56 为用户输入，已全部覆盖；`data-copy-target="${id}"` 的 id 为模块生成（`cb-`+uid） | 代码证明 |
| 黑名单拦截路径 | 拦截分支返回 `keep(escapeHtml(label))`——与旧行为等价（旧为返回已转义 label），直出时仍是转义文本 | 代码证明 |

**未发现利用正则边界、占位符或嵌套结构重新产生未转义属性的路径。C3 判定：PASS。**
